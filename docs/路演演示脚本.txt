「林海星火」路演演示脚本（v0.4 版）
════════════════════════════════════════════════════════

面向比赛路演（评委视角）。总时长建议 6-9 分钟，可裁剪。
配套数据：db_seed/stories-extra.json（6 条新故事）
        + trace_batches-extra.json（秋茬批次）
讲解原则：先感受真实，再谈转化——这正是产品理念本身。

────────────────────────────────────────────────────────
开场（30 秒）
────────────────────────────────────────────────────────
动作：手机打开小程序，展示首页（不要急着点）

讲解词：
  这是一款为森林生态农产品打造的"信任连接"小程序，叫林海星火。
  我们的核心问题：消费者凭什么相信深山里的木耳是真的、是安全的？
  我们的答案：不靠广告，靠透明。
  先感受这片林子的真实，再决定要不要带走它的一部分。

页面亮点：首页没有购买按钮——刻意设计（设计原则：首页不促成交易，
只建立信任）。

────────────────────────────────────────────────────────
第一幕：看见林子（1 分钟）
────────────────────────────────────────────────────────
动作：向下滑首页

讲解词：首页从上到下讲三件事：
  1. 林地影像——无人机季度更新，轮作区和对照区的植被差异；
  2. 生态数据看板——土壤有机质三个季度的变化曲线
     （A/B/C 三块对照样地），数据来自驻场团队实测；
  3. "正在发生"故事流——护林人的巡护记录、驻场学生的日记。

演示亮点：
  - 点一条故事 → 展开全文（内容完整可读）
  - 点"点赞" → 数字 +1 且杀进程重进仍在（真实上云）
  - （可选现场秀）后台发一条故事 → 回首页 → 立刻出现

────────────────────────────────────────────────────────
第二幕：溯源——信任的核心（1.5 分钟）
────────────────────────────────────────────────────────
动作：切溯源 tab → 点"扫一扫"（或点"体验档案"进秋茬木耳批次）

讲解词：每一件产品都有一个五维溯源档案：
  产地（真实 GPS 坐标，脱敏保留 2 位小数）、
  生长记录（关键节点照片）、环境数据（土壤温湿度曲线）、
  采收信息（谁采的、什么时候）、检测报告（高校实验室，PDF 可下载）。
  每份档案带唯一档案编号和时间戳——我们不引区块链，
  用严格的记录规程和透明呈现建立可信度。

演示亮点：
  - 扫码（真实扫码跳转档案）
  - 产地 tab → "查看样地位置"（微信内置地图展示脱敏坐标）
  - 分享档案给好友

答辩点：防篡改？→ 编号+时间戳+云端存储保证"记录可验证、环节可追问"；
区块链是加分项不是必需项。

────────────────────────────────────────────────────────
第三幕：研学——名额真实递减（2 分钟 · 本轮核心看点）
────────────────────────────────────────────────────────
动作：切研学 tab → 进"一日研学营"详情 → 念出当前名额
      （如"8月15日 余 13 位"）→ 报名一单 → 返回详情页
      → 再念名额（余 12 位！）

讲解词：
  研学有三档课程，预约有名额管控（每团 ≤20 人）。
  关键：这是真实的并发安全名额——报名由云函数用数据库事务原子校验，
  名额真实递减、满员自动拒绝，杜绝"超卖"。

演示亮点（按顺序）：
  1. 报名前念出名额数字 → 提交报名
     → 确认弹窗（演示流程，不产生真实扣款）→ 成功页（行前须知）
  2. 返回详情页 → 名额 -1 肉眼可见（若没刷新，切走再切回）
  3. 订阅消息授权弹窗：报名成功时点"允许"
     → 稍后微信"服务通知"收到推送（现场翻给评委看！）
  4. （加分秀）订单管理页删除该订单 → 回详情页 → 名额 +1 回来了

────────────────────────────────────────────────────────
第四幕：云认养（1 分钟）
────────────────────────────────────────────────────────
动作：切认养 tab → 展示三档计划 → 进"木耳菌棒认养"详情
      → 电子协议 → 确认 → 专属认养主页

讲解词：
  云认养三档计划（199 木耳菌棒 / 1999 红松+中药材 /
  19999 林下参限量 50 株）。
  电子协议 → 专属认养主页：季度生长报告、碳汇趣味报告（红松专属）、
  到期前 30 天续约提醒（真实日期计算，云端顺延）。

演示亮点：认养成功后同样有订阅推送；主页显示剩余天数真实计算。

────────────────────────────────────────────────────────
第五幕：后台与数据闭环（1.5 分钟）
────────────────────────────────────────────────────────
动作：切"我的"→ 后台管理（口令 linhai2026）
      → 依次展示：互动统计、反馈管理、巡护记录
      → 录一条采收建档 → 回溯源档案
      → 该批次自动多了"采收期"记录（数据自动汇聚！）

讲解词：
  管理侧：同一个小程序内嵌后台——故事发布、巡护记录（拍照上传 +
  真实 GPS 定位）、物候观测、采收建档、批次管理、订单管理、
  互动统计（点赞收藏真实聚合）、反馈管理。
  技术底座：微信云开发（数据库 16 集合 + 云函数 4 个 + 云存储），
  零服务器，学生团队可自主维护。

演示亮点：采收建档 → 档案页自动更新（前后台数据自动汇聚，现场可见）。

────────────────────────────────────────────────────────
结尾（30 秒）
────────────────────────────────────────────────────────
讲解词：
  这套系统完成了从"感受"到"信任"到"转化"的完整闭环，
  且全部业务数据真实落云。
  受个人主体限制，在线支付为演示流程，架构已预留升级位
  （取得企业主体即可接入真实支付）。
  项目已开源（GitHub），从零开发用时约三天。谢谢。

答辩预备问题：
  - 数据哪来的？→ 驻场团队实测，后台录入；当前为演示数据
  - 为什么不用区块链？→ 成本与必要性权衡，透明呈现+严格规程已足够
  - 个人主体限制？→ 支付/类目受限，已标注升级路径（企业主体）
  - 技术栈？→ 原生 MINA + 云开发（16 集合/4 云函数/云存储），
    事务防超卖、订阅推送、数据汇聚均已实现

演示前检查清单
────────────────────────────────────────────────────────

  [ ] 已导入 stories-extra（6 条新故事）与 trace_batches-extra（秋茬批次）
  [ ] 首页故事流 8-10 条，含 2-3 条可展开长文
  [ ] 溯源档案至少 3 个批次可点开（含秋茬批次五维完整）
  [ ] 研学名额充裕的日期（提前确认"一日研学营 8月15日"有名额）
  [ ] 认养主页有 1 条认养记录（提前认养一条）

【设备与网络】
  [ ] 真机打开小程序（模拟器 ≠ 真机，路演必须真机）
  [ ] 网络稳定（云数据库依赖网络；弱网会回退演示数据）
  [ ] 手机亮度调高、关闭消息打扰（但保留微信通知权限——推送演示要用）

【推送演示】
  [ ] 已授权过订阅消息（路演当天首次授权即可）
  [ ] 现场能打开"微信 → 服务通知"（提前确认入口位置）

【后台】
  [ ] 后台口令 linhai2026 可用
  [ ] 有一块可现场演示"采收建档→档案自动汇聚"的批次

【走场】
  [ ] 全流程彩排 1-2 遍（对照本脚本逐步走）
  [ ] 计算好时间（6-9 分钟）；超时预案：砍第五幕汇聚演示或第四幕认养
